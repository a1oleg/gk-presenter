# Конвейер двух независимых сцен

```powershell
npm run pipeline -- --plan examples/pipeline-fisher.json
```

Одна команда читает исходные `.drawio` и файл кода, экспортирует выбранный фрагмент
диаграммы, создаёт снимок кода с семантическими цветами, проверяет компоновку,
рендерит `diagram.mp4` и `code.mp4`, затем собирает `composed.mp4`.
Общая запись окна VS Code не используется. Таблица, TTS и публикация не вызываются.

Для подготовки материалов и проверки без видеорендера:

```powershell
npm run pipeline -- --plan examples/pipeline-fisher.json --prepare-only
```

## План

Пример зависит от соседних проектов `coldKode` и `drawio-inspector` и установленных
зависимостей Motion Canvas/TypeScript. Названия тем и пути не зашиты в конвейер:
укажите свои значения в плане. Пути разрешаются относительно файла плана.

- `diagram.file`: исходная диаграмма. `cellIds`: явный набор узлов или групп.
  Экспорт включает их целые поддеревья и связи между выбранными узлами.
  Остальные элементы скрываются только в копии модели рендера; исходный XML
  не изменяется. Связи с невключёнными узлами не показываются.
- `diagram.minimumScale`: минимальный итоговый масштаб относительно координат
  draw.io. Если фрагмент слишком велик для своей дорожки, сборка останавливается.
  Это числовой порог масштаба, а не автоматическая оценка читаемости текста.
- `code.file`, `code.lines`: файл и упорядоченные включительные диапазоны строк.
  Пробелы, пустые строки и исходные номера сохраняются.
- `code.semanticRoot`: каталог с `classify.js` и `extension.js`, откуда берутся
  семантическая классификация и палитра редактора. Исполняйте только доверенные
  локальные адаптеры. `fontSize`/`minimumFontSize` задают пределы размера шрифта.
- `canvas`, `tracks`, `font`, `durationSeconds`: параметры монтажа,
  описанные также в [контракте независимых сцен](INDEPENDENT-SCENES.md).
- `events`: `diagramCell`, `codeLine` и либо `time`, либо `anchor`.
  При повторении слова задайте `occurrence`, начиная с 1. События должны идти
  по времени и находиться внутри выбранной длительности.
- Необязательное `audio`: `file`, а для словесных якорей также `alignment` и
  `narration`. Текст файла `narration` должен точно совпасть с текстом выравнивания,
  включая пробелы и переводы строк. Выравнивание не доказывает соответствие аудио:
  нужно использовать готовую пару аудио/выравнивания одного запуска синтеза.

Пример `pipeline-fisher.json` работает без звука. Чтобы использовать готовую
озвучку, добавьте `audio.file`; временные метки должны соответствовать этому аудио.

## Результат и продолжение работы

Каждый запуск создаёт `pipeline-*` в настроенном `materials.local.json` хранилище.
Там лежат исходный план, снимок кода, копия диаграммы, её чистый экспорт и геометрия,
`composition.json`, а после рендера — каталог `render` с двумя дорожками,
композицией, кадрами и отчётом проверки.

`pipeline-report.json` содержит стадии, хеши источников и статус `prepared`,
`complete` или `failed`. При ошибке сохранены стадия и причина, чтобы человек
или агент мог исправить план. Новый запуск создаёт отдельный результат.
Подготовленную композицию можно отдельно отрендерить командой
`python scripts/render_independent_scenes.py <путь-к-composition.json>`.

Горизонтальная камера во время клипа не меняется. Выделения переключаются по
таймингам; плавные переходы между фрагментами и автоматическая генерация текста
не входят в этот путь. При изменении исходного кода старый снимок отклоняется.
