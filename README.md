# coldKode Presenter

Локальная мастерская технических объяснений: исходная речь автора + доказательства из кода и графа + визуальный план + синтез авторского голоса.

Цель — сохранять манеру автора, но делать объяснения точнее, короче и понятнее. Не имитировать уверенность при недостатке доказательств.

## Текущее состояние

Это начальный репозиторий, не готовый генератор видео. Реализован проверяемый контракт сценария и его валидатор. Распознавание речи, доступ к графу, синтез голоса и монтаж ещё не подключены. Нет загрузки пользовательских данных в облако, скачивания моделей или платных вызовов.

## Запуск

Нужен Node.js 22+. Зависимостей пока нет.

```powershell
npm test
npm run check
node src/check-lesson.mjs path/to/lesson.local.json
```

Валидатор проверяет структуру и ссылки между утверждениями, доказательствами и кадрами. Он не доказывает истинность текста и не открывает исходники.

## Как устроен будущий процесс

1. Подключить оригиналы видео и аудио по локальным путям, не перемещая их. Проверить длительности и сдвиг дорожек. Отдельное аудио не считать автоматически синхронным.
2. Сделать расшифровку с временными метками. Отделить оговорки и повторы от ценных авторских объяснений.
3. Через существующий оркестратор coldKode получить код, пути графа и готовые аннотации. Не создавать второй экстрактор и не зависеть от визуальных плиток. Фиксировать ревизию источников; старое видео может описывать старый код.
4. Собрать пакет доказательств для выбранной темы. Аннотация — вспомогательный источник, а не замена проверке реализации.
5. Подготовить сценарий и кадры: одна мысль, её доказательства, нужный фрагмент диаграммы, произношение терминов. Не показывать сразу весь граф.
6. Автор утверждает текст. Затем синтезировать речь по коротким фрагментам и измерить фактическую длительность. Подстроить кадры под речь, а не ускорять голос ради заранее придуманного тайминга.
7. Собрать аудио, визуалы и монтажный план. Проверить ударения, термины, смысл, соответствие изображения речи; только затем экспортировать ролик.

## Первый эксперимент

Выбрать 60–90 секунд из 40-минутного видео. Подготовить три версии: оригинал; улучшенный текст; улучшенный текст с клонированным голосом. Сравнить смысловую точность, понятность, узнаваемость голоса, темп и количество ручных исправлений. Измерить время генерации / длительность аудио на имеющемся CPU, прежде чем выбирать движок для полного ролика.

XTTS-v2 — кандидат, не зафиксированный выбор: требуется проверить качество русского, скорость на CPU и условия лицензии для предполагаемой публикации. Дискретная видеокарта не предполагается. Для отбора образца использовать чистую речь одного человека без музыки; не скармливать все 40 минут короткореференсному движку.

## Данные и безопасность

- `data/`, `output/`, `models/`, `*.local.json` не входят в Git. Локальные пути задаются в `sources.local.json`, шаблон — `examples/sources.example.json`.
- Только голос владельца с его согласием. Исходники не изменять и не удалять.
- Голосовые образцы, содержимое экрана, ключи API и персональные данные не публиковать. `.gitignore` не заменяет проверку перед публикацией.
- Облачные сервисы подключать только после явного выбора пользователя; локальный запуск по умолчанию.
- Автоматическая публикация на YouTube не входит в начальный объём.

## Контракт сценария

См. `examples/lesson.json`. `evidence` хранит ссылки на источники; `claims` связывает технические утверждения с доказательствами; `segments` связывает речь и визуал с этими утверждениями. `targetSeconds` — ориентир, не измеренный результат TTS. `profile` описывает аудиторию и авторскую манеру, `pronunciations` — проверенные варианты произношения.
