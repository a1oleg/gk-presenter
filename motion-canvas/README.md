# Титры Motion Canvas

Сценарий хранится в `scenario.json` рядом с видео. В нём отдельные разделы:
границы диаграммы (`stableId`), состояние титров, звуковая дорожка, словесные
маркеры указок и рассчитанные координаты. Google Sheets остаётся редактором данных.

`npm ci`, затем `npm run serve` запускают локальный редактор на 127.0.0.1:9031.
Из корня presenter:

1. `scripts/prepare_motion_scene.py` фиксирует данные строки 11 и ФЙ-сценария,
   проверяет совпадение текста и использует уже готовую озвучку 3.3.
2. `node scripts/resolve_motion_layout.mjs <папка>` вычисляет титры справа
   от верхнего узла. При пересечении с целевой строкой кода останавливается
   и сообщает требуемый сдвиг, а не записывает заведомо перекрытый кадр.
3. `node scripts/render_motion_captions.mjs <папка>` рендерит прозрачные PNG
   через Motion Canvas. Титры плавно появляются; экран приложений не перерисовывается.
4. `node tmp/record-row11-fixed.mjs <папка>` записывает реальные окна и указки,
   проверяя неизменность камеры и согласованного положения кода.
5. `scripts/finish_motion_scene.py <папка>` накладывает титры, проверяет видео,
   затем обновляет K11, только если исходные ячейки не изменились.

Для Python используются зависимости существующих окружений presenter и Sheets MCP.
PNG-экспорт запускается в headless Chrome, OBS пишет исходную сцену. Микрофонная
дорожка в результат не включается.

## Координаты и ограничения

`src/caption-layout.mjs` работает в пикселях итогового видео. Прямоугольник титров,
его тень и зазор до кода сохраняются в `layout-check.json`. Привязка к диаграмме
использует геометрию узла, текущую камеру и преобразование области захвата.

Первая версия откалибрована для 1920×1080, окна VS Code 1920×1032, OBS cropTop=132,
positionY=90, высоты строки 28 px и двух колонок. Это НЕ универсальное определение
DOM-координат редактора: при смене шрифта, DPI или расположения нужна новая
калибровка. Проверяется целевая строка и последующий код; более ранние строки
выше неё могут попадать под панель. Автопрокрутка пока не реализована:
планировщик возвращает требуемый сдвиг, прокрутку выполняет управляющий агент.

Контент из таблицы не исполняется как JS. Секреты и аудио в репозиторий не входят.
# Независимые области диаграммы и кода

Режим `dual-scene` не записывает вторую вкладку VS Code. OBS записывает
полноширинную draw.io-диаграмму, а Motion Canvas накладывает собственный `Code`
и титры. Исходник и семантические цвета берутся из реального TypeScript-файла
и общего классификатора `vscode-source-colors`.

- Верхний/нижний узлы определяют масштаб диаграммы по высоте через MCP bounds.
- Правая граница указанной мозаики + 32 px определяет начало области кода.
- Код начинается на 40 px ниже титров; размер шрифта подбирается по ширине.
- Номера строк сохраняются из исходника. Указка получает координаты символов
  через `Code.getSelectionBBox`, а не через пиксельное распознавание.
- Проверяются границы каждой строки, доступное место, неизменность камеры
  и неизменность исходных ячеек перед публикацией.

Команды для текущего фрагмента: `prepare_motion_scene.py`, затем
`prepare_code_preview.mjs <out>`, `resolve_dual_scene.mjs <out>`,
`render_motion_captions.mjs <out>`, `tmp/record-row11-fixed.mjs <out>` и
`finish_motion_scene.py <out>`. Метаданные, геометрия, карта строк и настройки
композиции сохраняются рядом с видео. Текущая ссылка результата — L11.
