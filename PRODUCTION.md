# Производство видео из одного сценария

`lesson.json` теперь может содержать исполняемую секцию `production` и поле
`render` у каждого сегмента. Связи текста с утверждениями и источниками проверяются
тем же валидатором, что и раньше. Порядок `segments` определяет порядок монтажа.

```powershell
npm run produce -- --lesson examples/production/fisher.json --check
npm run produce -- --lesson examples/production/fisher.json
npm run produce -- --lesson examples/production/consensus.json
```

Два примера используют одинаковые команды и реализацию, но разные темы, размеры
кадра и FPS. Это короткие **демонстрации без озвучки**, с искусственными ссылками
на свидетельства; они проверяют механику сборки, а не достоверность объяснений.
В примерах указан Windows Arial. На другой машине измените `production.font`.

Нужны Node.js 22+, Python в `.venv`, пакеты `av`, `Pillow`, `imageio-ffmpeg`.
Каталог вывода берётся из обязательного `materials.local.json`. Каждый запуск
создаёт новый каталог `production-*`, сохраняя входной сценарий, исполняемый план,
видео сцен, кадры для просмотра, `movie.mp4` и `production-report.json`.
`--check` читает и декодирует источники, проверяет тайминги и размещение текста,
но не создаёт медиаматериалы. Сервис браузерного рендера для этого пути не нужен.

## Параметры

- `production.version`: `1`; `canvas`: чётные `width`/`height` от 64 до 3840 и
  целый `fps` от 1 до 60; `background`: цвет `#RRGGBB`; `font`: путь к TTF.
- `render.background`: `{ "kind": "solid" }` либо
  `{ "kind": "image", "file": "assets/frame.png" }`. Изображение вписывается
  без обрезки, сохраняет пропорции и дополняется цветом фона.
- `render.audio`: `{ "mode": "silent" }` либо
  `{ "mode": "file", "file": "assets/speech.wav" }`.
  Для режима без речи обязательна `durationSeconds`. При готовой озвучке
  длительность определяется декодированным аудио; `targetSeconds` остаётся
  редакционным ориентиром. `tailSeconds` — пауза после сцены, по умолчанию 0.3.
- `render.overlays`: массив слоёв `text` и `pointer`. Координаты `x`/`y` от 0 до 1,
  `size` в пикселях, `color` в формате `#RRGGBB`. Для текста обязательно `text`;
  переносы строк задаются явно. Выход за рамки кадра вызывает ошибку.
- `start`/`end` слоя задаются в секундах либо как
  `{ "anchor": "слово", "occurrence": 2 }`. Для словесных якорей задайте
  `render.audio.alignment` — JSON с `characters` и
  `character_start_times_seconds` (также принимается объект `alignment`).
  Текст выравнивания должен совпадать с `narration`; повторяющийся якорь требует
  явного номера вхождения, начиная с 1.

Относительные пути к входным файлам разрешаются относительно сценария.
SHA-256 источников фиксируются в плане и проверяются перед и после рендера.
Для каждой сцены и итогового видео проверяются число кадров, размер, FPS,
наличие аудиопотока и соответствие его длительности видео.

## Границы этой реализации

Это общий путь **подготовленный фон + текст/указка + готовое аудио → сцены → ролик**.
Он не вызывает TTS, не изменяет таблицу и не публикует видео. Существующие скрипты
захвата интерфейса, живого draw.io, специальных виджетов Fisher–Yates и исправления
озвучки остаются отдельными средствами подготовки материалов. Плавное движение
камеры/указки и специальные виджеты не поддерживаются этим рендерером.

Следующая интеграция — адаптеры получения фона и аудио, которые выдадут те же
входные материалы и будут запускаться отдельно с проверкой результата.

## Проверка реализации

Unit-тесты: `npm test`. Интеграционная проверка: `.venv\Scripts\python.exe -X utf8 scripts/verify_production.py`.

Она создаёт синтетическое изображение и тестовый тон, собирает видео и проверяет Unicode, тайминг якоря, границы текста, длительности и SHA-256. Тон не является озвучкой; выравнивание в этом тесте искусственное. Материалы проверки остаются в настроенном каталоге output.
